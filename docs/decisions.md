## 2026-10-11 — the acceptance tier

| # | Decision | Why | Lands in |
|---|---|---|---|
| D16 | **Acceptance is a mode, `sightline accept`, not a skill. Exit 0 by default; `--strict` exits 1 on any `fail`, 2 when nothing could run (build failed, runner unavailable), never non-zero for `not_verifiable` alone. A criteria file that fails lint never runs and exits 2** | Verdicts, including `pass`, for criteria an author chose, are a different contract from findings on a diff. An agent loop needs an exit code, and must not read "didn't build" as "nothing failed" | [ADR-0004](adr/0004-acceptance-tier.md) §1, §8 |
| D17 | **Log evidence comes from `SIGHTLINE-AC\|` lines committed in the app, at `.notice`, with a configurable subsystem.** Sightline never writes app source; the Claude Code skill proposes them as diffs, left staged. Lines are attributed by launch window and confirmed by PID; anything but exactly one PID is `log_unavailable` | `.debug` never reaches the bundle and app output is one file per run (verification V1, V3). Fail-closed liveness is what keeps broken capture from reading as "observed zero" — proven by corpus case 007 | ADR-0004 §5, `core/acceptance/derive.py` |
| D18 | **A crash is `not_verifiable(app_crashed)`, listed first; an unreachable step is `not_verifiable(step_unreachable)`, listed loudly; an absent element is a `fail` only if the criterion asserts `exists: true`, otherwise `no_observable`** | A crash is not the `then` observed false, and a wrong identifier in the criteria looks identical to a missing control. Lint warns on every observation without `exists` | ADR-0004 §3 |
